How I built my portfolio with Claude Code

The useful part wasn’t asking AI to write more code. It was giving it a smaller, clearer system to reason inside — then reviewing each decision before it shipped.

01

What I built

A single-page portfolio for technical recruiters — built to lead with real numbers, not generic copy, and to make the engineering behind it visible.

The brief was intentionally focused: create a fast, legible surface for enterprise digital platforms, APIs, and cloud systems, then use the build itself as a case study in AI-assisted engineering.

Structure

Single page

One deliberate narrative instead of a maze of pages.

Discoverability

SEO & GEO

Structured data, a clear site map, and explicit crawler guidance.

Delivery

CI/CD

A repeatable path from a merged change to a live site.

Trust

Analytics

Enough signal to learn what works without tracking people around.

02

Tech stack

No framework, no server, no CMS. A small, legible surface is easier for both a person and an AI agent to understand correctly on the first try.

Frontend

Bootstrap + Sass

Utilities, components, design tokens, self-hosted Inter, and inline SVG icons.

Build tooling

Vite

Multi-page output, with the blog and homepage defined as explicit build entries.

Hosting

S3 + CloudFront

Private bucket, CDN delivery, Route 53, and ACM for DNS and TLS.

Automation

GitHub Actions

Build, sync, invalidate, and authenticate with IAM OIDC — no static AWS keys.

03

Claude Code

Claude Code works best for me as a collaborator inside a system of constraints — not as an agent I hand a giant prompt and a blank canvas.

Most of my prompts are surprisingly short. They work because I spend the effort on the context around the prompt: persistent instructions, focused sessions, task-specific rules, and review artifacts the agent can work through one step at a time. Four habits do most of the work.

03.1

Write your stack down once, then keep every prompt short

Stop re-explaining your stack in every prompt. Put the context in the repo once, and let the prompts get short.

I don’t open sessions with paragraph-long preambles about my tech stack, styling preferences, or design rules. That persistent context lives in a CLAUDE.md file at the root of the repo, and it loads automatically into every session.

03.2

One project, six personalities

Don’t stuff every rule into a single file. Swap context files when you swap work phases.

A single CLAUDE.md covering design, content tone, SEO, accessibility, and deployment scripts gets noisy fast. Instead I keep specialised instruction files, one per project mode:

Moving from UI work to SEO tuning, I don’t cram new rules into the live conversation — I swap the relevant file into CLAUDE.md and start a fresh session.

Why it works

You change the agent’s operating lens instead of fighting context-window degradation. It evaluates the codebase against one laser-focused set of domain constraints at a time.

03.3

The 15% rule: restart before the agent drifts

One focused session per meaningful unit of work. Long conversations breed sloppy code.

It’s tempting to leave one session open for hours, but long contexts accumulate hallucinated variables, obsolete errors, and stale instructions. My heuristic: restart once context usage hits ~15%, or whenever a distinct task is done.

03.4

Review artifacts: turn loose audits into executable checklists

Never ask an agent to “review and fix everything.” Make it write a Markdown task tracker first.

Asking for a sweeping fix invites sweeping, unexpected changes. Instead I make the agent commit an explicit review artifact to the repo before it touches a line of code.

05

Conclusion

The results came from a disciplined system, not from prompt engineering.

Four habits did the work — the same four from §3, in the order they mattered. Together they turned the agent into a high-precision execution tool.

  1. 01

    Write CLAUDE.md once, save time forever

    Keeping the architecture rules in the repo meant every build command could stay short and precise.

  2. 02

    Change operating lenses as you work

    Swapping context files for UI, SEO, and CI/CD kept the agent judging the codebase against only the constraints that applied.

  3. 03

    Start fresh before the agent drifts

    Restarting around ~15% context usage stopped stale bugs and accumulated noise from working their way into clean code.

  4. 04

    Make the agent build its own task list

    A Markdown checklist gave me full oversight before a single file changed.

Claude Code accelerated the build, but the system around it kept me in control. AI-assisted engineering isn’t about typing fewer lines of code — it’s about building the constraints that make execution clean and predictable.
